# 《星算速算家》UI 设计规格书（UI_SPEC）

版本 v1.0 ｜ 设计：颜如绘 ｜ 日期 2026-10-03
设计基准画布：**672 × 1280 px**（竖屏 9:16，与参考视频 1:1）
渲染方式：原生小游戏 Canvas 2D 自绘

---

## 0. 通用约定

### 0.1 单位换算

| 项 | 值 |
|---|---|
| 设计稿基准 | 672 × 1280 px |
| rpx 等价 | 750 rpx = 屏宽；**1 设计 px = 1.116 rpx** |
| 安全区（顶部） | y = 0 ~ 96（状态栏 + 微信胶囊） |
| 微信胶囊矩形 | x 578 ~ 665，y 40 ~ 76 → **该区域禁止放任何可点元素** |
| 安全区（底部） | y = 1220 ~ 1280（全面屏手势条，含 iPhone 34pt 区域） |
| 内容安全宽度 | x = 16 ~ 656（左右各留 16px 外边距） |
| 圆角基准 | 8 / 12 / 16 / 20 / 28 / 999（胶囊） |
| 描边基准 | 卡通粗描边 5px（主）、3px（次）、2px（内部分隔） |
| 硬阴影 | `offsetY = 描边宽度`，零模糊，纯色 `#3D2B6B`——与参考视频一致的三重"贴纸"质感 |

### 0.2 字体栈

```
/* 中文正文与标签 */
font-family: "PingFang SC", "HarmonyOS Sans SC", "Source Han Sans CN",
             "Noto Sans SC", "Microsoft YaHei", -apple-system, sans-serif;

/* 数字（算式 / 键盘 / HUD 分数）——必须圆润、字宽稳定、等高 */
font-family: "SF Pro Rounded", "Baloo 2", "DIN Alternate", "Arial Rounded MT Bold",
             "PingFang SC", sans-serif;
font-variant-numeric: tabular-nums;   /* 防跳动 */
```

> 数字必须用 `tabular-nums` 或等宽回退，否则倒计时/分数数值变化时整块 UI 会左右抖动。

### 0.3 视觉层级（z-index，自下而上）

| z | 层 | 内容 |
|---|---|---|
| 0 | 背景层 | 垂直渐变 + 年级装饰（云/星/网格） |
| 10 | 光晕层 | 角色背后的径向柔光 |
| 20 | 角色台层 | 粉色台面 + 台面装饰 |
| 30 | 角色层 | 主角 PNG（分 normal / front 两种 z，见 §5.5） |
| 40 | 粒子层（后） | 彩带、灰尘 |
| 50 | 题目白卡层 | 白卡 + 算式 + 答题位 |
| 60 | 特效层（前） | 冲击波、粒子迸发、高光扫过 |
| 70 | HUD 层 | 顶部 HUD + 数据条 |
| 80 | 关卡横幅层 | EX N 斜切彩带（覆盖角色上部） |
| 90 | 弹窗/Toast 层 | 暂停、结算、家长提示 |

### 1.8 字号阶梯（设计 px @672 基准，附 rpx）

| Token | px | rpx | weight | 用途 | 对比度要求 |
|---|---|---|---|---|---|
| `fs-equation` | **64** | 71 | Bold | **算式主数字（第一视觉焦点）** | `ink-900` on 白 ≥ 7:1 |
| `fs-answer` | 56 | 63 | Bold | 答题圈内已输入数字 | `error-600` on 白 ≥ 4.5:1 |
| `fs-ex` | 56 | 63 | Bold | 关卡横幅 `EX N` | 白 on `brand-700` ≥ 9:1 |
| `fs-timer` | 48 | 54 | Bold | 倒计时 `0:07` | `ink-900` on `surface-card` |
| `fs-key` | 46 | 51 | Bold | 数字键 0—9 | `ink-900` on 键面 |
| `fs-score` | 38 | 42 | Bold | 总分数字 | `ink-900` on `accent-gold` |
| `fs-hud-label` | 24 | 27 | Bold | 正解 / 失误 / 连击 标签 | 见各容器 |
| `fs-tag` | 26 | 29 | Bold | 题型标签胶囊文字 | 白 on `brand-600` = 5.78:1 ✅AA |
| `fs-qindex` | 28 | 31 | Bold | 「第 N 问」 | `ink-700` |
| `fs-body` | 26 | 29 | Regular | 提示语、Toast | `ink-500` on 浅底 |
| `fs-caption` | 20 | 22 | Regular | 单位、版权、辅助提示 | `ink-500` |

**层级规则**：`fs-equation (64) > fs-answer/fs-ex (56) > fs-timer (48) > fs-key (46) > fs-score (38)`。
算式数字必须 ≥ 键盘数字 1.35 倍，否则孩子会分不清"题目"和"输入"。

**自适应缩放**：当算式超过 6 个字符（如三位数÷两位数带余数）时，整组算式按 `min(1, 420 / 实测宽)` 等比缩放，最小缩到 0.72（≈46px），**不得换行**。

### 3.4.1 答错时显示正确答案（v1.3 新增，team-lead 决策）

**设计意图（Feedforward 原则）**：答错后**不只告诉孩子"错了"，而是让他立刻看到正确答案是多少**。这是最省力的自我校正路径——不需要大人讲题、不需要查错题本，下一题就会自然带出记忆。

**核心约束：不用红色。** 红色 = 负面情绪。正确答案应呈现为**"这是一份馈赠"**，用金色描边。

| 阶段 | 时长 | 表现 |
|---|---|---|
| ① 抖动 | 320ms | 保持 §3.4 原有抖动 |
| ② 错误值淡出 | 160ms | 用户输入的数字向左平移 24px + 淡出（`error-600`） |
| ③ 正确答案入场 | 200ms | 从答题位中心 scale 0.7→1.0 + 淡入，色 `brand-700` |
| ④ 金色描边强调 | 240ms 后 | 圈线宽 8→4，颜色由 `error-600` 过渡到 `accent-gold-deep`，**闪 2 次**（每闪 180ms） |
| ⑤ 停留 | **1200ms** | 正确答案清晰可读，角色播 `wrong` 轻量版 |
| ⑥ 淡出 | 200ms | 整圈淡出，进入下一题 |

| 元素 | 规格 |
|---|---|
| 正确答案文字 | `fs-answer(56)` Bold，色 `brand-700`（**不是** `error-600`，**不是**金色填充——避免与「答对」混淆） |
| 圈线最终色 | `accent-gold-deep` `#E09A00`，线宽 4px |

| 状态 | 圈色 | 字色 | 含义 |

### 6.2 屏幕震动分级表

震动通过 **Canvas 整体 translate** 实现（不使用 `wx.vibrateShort`，避免低端机卡顿与家长反感；系统触感由家长开关统一映射）。

| 等级 | 触发条件 | 幅度（px） | 时长（ms） | 频率 | 备注 |
|---|---|---|---|---|---|
| L0 | 连击 0—4 答对 | 0 | 0 | — | 仅角色动画 |
| L1 | 连击 5—9 答对 | 2 | 60 | 30Hz | 几乎不可感，防疲劳 |
| L2 | 连击 10—19 答对 | 4 | 80 | 30Hz | |
| L3 | 连击 20—29 答对 | 6 | 100 | 35Hz | + 光晕同步脉冲 |

### 7.2 差异化实现要点

| 项 | 规则 |
|---|---|
| 切换时机 | 选定年级后**立即生效**，写入 `wx.setStorageSync('grade')`，跨会话保持 |
| 缩放实现 | 全局 `ctx.scale(gradeScale, gradeScale)` **不推荐**（会导致描边粗细失真）。应在布局函数中读取 `layout.equationFontSize` 等参数，各元素独立计算 |
| 装饰层性能 | 背景装饰绘制在离屏 canvas 上，**只在年级切换时重绘一次**，每帧只 `drawImage` 一次 |
| 1—2 年级额外 | 键盘键位改为「圆形」变体（圆角 = 高度/2），更圆润友好 |
| 5—6 年级额外 | 题目白卡支持显示"提示：先算乘法"这类灰色小字（`fs-caption`，`ink-500`），由后端按题型下发 |

### 7.3 低年级字号加码（v1.3 新增，team-lead 决策①⑤）

**问题**：v1.2 方案是**全局下调字号**以解决小屏可读性。但这会破坏 §1.8 已逐项验算过的 WCAG 对比度组合（字号变小 → 同一对比度下容错下降），且高年级本来就该更简洁。

**决策**：**不做全局下调，改为 1—2 年级整体加码 +2px，高年级不变。**

理由：低年级孩子的手部控制与视觉发育尚未成熟，**本就需要更大字**。加码不触碰对比度下限（字号变大只会让 WCAG 达标更宽松），且符合"按年龄差异化"的产品逻辑。

| 元素 | 1—2 年级 | 2→1 变化 | 高年级 |
|---|---|---|---|
| 算式数字 | **74 px** | 72 → 74（+2.8%） | 56 px（不变） |
| 键盘数字 | **54 px** | 52 → 54（+3.8%） | 42 px（不变） |
| 题型标签 | **28 px** | 26 → 28（+7.7%） | 26 px（不变） |
| 键高度 | 88 px | 不变 | 78 px（不变） |
| 卡内底部提示 | **22 px** | 20 → 22 | 20 px（不变） |

**连带校验**：

| 项 | 结果 |
|---|---|
| 74px 算式在白卡（宽 632，eq 区 370）内是否溢出 | 74×0.72 = 53.3px 缩放后仍清晰，**不溢出** ✅ |
| 74px 是否触发 §1.8 的自动缩放下限 | 缩放下限 = 74 × 0.92 = 68.1px，**远高于 41.5px 的可读底线** ✅ |
| 54px 键盘数字在 204px 宽键内 | 数字宽 ≈ 54×0.6 = 32.4px，**居中留白充足** ✅ |
| 28px 题型标签胶囊（高 46） | 字高 28 < 46 − 上下留白，**不溢出** ✅ |
| 与 `fontScale` 叠加 | 走 §19.4 三道钳制，最高 88px 上限，**不冲突** ✅ |

> **实现方式**：在 `grade` 配置对象里给 1、2 年级档位单独设 `fontBoost: 2`，统一在 `theme.js` 的字号取值函数里 `add(gradeCfg.fontBoost)`。**不要在各处硬编码 +2**。

### 7.4 主页「最高分」的年级差异化（v1.3 新增，team-lead 决策①）

**问题**：v1.2 的年级卡右下角固定显示「最高分 24,860」。对一年级孩子，首次游玩时必然是「最高 0 分」——**"0" 在低龄孩子眼里等于"我失败了"**，而它实际含义是"你还没玩过"。

**决策**：

| 年级 | 年级卡右下角 | 理由 |
|---|---|---|
| **1—2 年级** | **不显示「最高分」行**。改为显示空态引导 | 避免"最高 0 分"的挫败感 |
| 3—6 年级 | 照常显示「最高分 XXX」 | 已具备成绩比较的心智能力 |

**1—2 年级空态样式**（两张卡对照）：

| 元素 | 有成绩时（二年级及以上） | 无成绩时（一年级 / 首次） |
|---|---|---|
| 标签 | `最高分`（`fs-caption(20)` `n-300`） | `来试试`（`fs-caption(20)` `n-300`） |
| 数值 | `24,860`（`fs-caption(20)` `ink-500`） | `第一个记录`（`fs-caption(20)` `brand-600`） |
| 修饰 | — | 数值左侧加 ⌀16 小星图标（`accent-gold`），代替数字 |

```
一年级未游玩          一年级已游玩
┌──────────────┐     ┌──────────────┐
│    一年级     │     │    一年级     │
│   DL 1.0     │     │   DL 1.0     │
│  ★ ★ ☆ ☆ ☆   │     │  ★★ ★ ☆ ☆ ☆   │
│  熟练度 0     │     │  熟练度 1     │
│  ⭐第一个记录  │     │  最高 1,240  │  ← 二年级起才显示
└──────────────┘     └──────────────┘
```

> **判定条件**：`bestScore === 0` → 空态。**注意不要用"是否有游玩记录"判定**——玩了但全错也会是 0 分，那正是最需要鼓励的场景，此时应显示「第一个记录」而不是「0」。

## §12 难度微调器 UI

### 12.1 为什么不用滑杆

后端约定 `difficultyOffset ∈ [-3, +3]` 整数。滑杆（Slider）对小学生来说**无法精确停在整数**，会出现"我明明拖到中间怎么变成 +2 了"的困惑；且儿童手指拖拽精度差，滑杆是典型的**误触高发控件**。

**改用 7 段分段按钮**（`-3 -2 -1 0 +1 +2 +3`），中间 `0` 最宽，两端对称收窄，形成"以标准难度为中心"的视觉隐喻。

## §15 错题本与复习页

### 15.1 复习页是独立视觉体系（★ 重要）

复习**不是闯关**。必须换一套视觉，否则孩子会带着考试压力去做本来该零压力的巩固练习。

| 维度 | 闯关页 | **复习页** |
|---|---|---|
| 背景 | 粉紫渐变 + 装饰 | **纯色 `bg-top` 平涂，无渐变无装饰** |
| 倒计时 | 有（胶囊 + 软条） | **完全没有**（§6.6 细则 3） |
| 顶部 HUD | 进度点阵/倒计时/总分/数据条 | **全部移除**。替换为复习专用条（见下） |
| 关卡横幅 | `EX N` 斜切彩带 | **无横幅**。改用静态页标题 |
| 角色台 | 粉色台面 + 待机角色 | 保留角色（这是情绪锚点），但台面改为平涂 `n-50` |
| 题目白卡 | 描边 5px `ink-900` | 描边 3px `brand-300`（更轻） |
| 错误反馈 | 抖动 + 红色 | **不抖动、不变红**。算式停留 2s + 手写描红动画 + 「再看看这道题」 |
| 正确反馈 | 跳跃 + 粒子 | 角色跳跃 + 6 颗粒子（**减半**，不铺张） |
| 跳过 | 无 | **常驻可见**「跳过这题」 |

### 15.2 三种复习模式的 UI 差异

| 模式 | 适用 | 答题区 | 关键设计 |
|---|---|---|---|
| 🟢 **认一认**（Learn） | mastery 0—1、1—2 年级 | **无输入区**。只展示算式 + 正确答案 | 两个大圆钮：👍 `记住了`(x 96, y 700, ⌀180) / 👎 `再看看`(x 396, y 700, ⌀180)，面 `n-0`，描边 5px，选中反馈为 scale 0.94 + 描边加粗 |
| 🟡 **练一练**（Practice） | 1—3 年级 | **3 选 1**：三个大按钮横排 | 按钮 (x 40 / 244 / 448, y 690, 宽 184, 高 200, r28)，面 `n-0`，描边 5px `brand-700`，数字 `fs-equation(64)` Bold `ink-900`。**★ 干扰项来自后端 `lastWrongAnswer`（孩子上次答错的数）——把他自己错过的数当诱饵，纠正效果最强** |
| 🔴 **考一考**（Quiz） | 4—6 年级 | 复用 §2.7 完整数字键盘 | 无软倒计时条；数字键布局不变 |

> **年级自适应规则**（后端 §6.6）：`grade ≤ G2` → 两段式「认一认 → 练一练」，**不出现输入键盘**；`grade ≥ G3` → 「练一练 → 考一考」。
> UI 实现上，这意味着 1—2 年级走复习时**要把 §2.7 的键盘区域换成 3 选 1 按钮区**，这是布局级别的差异，不是只换文案。

### 15.3 答错时的「手写描红」（§6.6 细则 5 的视觉实现）

| 阶段 | 时长 | 表现 |
|---|---|---|
| 停留 | 2000ms（不可跳过） | 算式静止，**不出现"错"字、不变红、不抖动** |
| 描红 | 600ms | 正确答案以 `error-400` 笔触从左到右描出（模拟手写），线宽 6，端点圆头 |
| 语音/提示 | 与描红同步 | Toast「再看看这道题」`(336, 620)`，`fs-body(26)` `ink-500`，**无红底** |
| 角色 | 同步 | 角色切换到 `wrong` 的**轻量版**：只缩小 0.94 + 1 颗汗滴，**不摇头、不变色** |

**`loading` 骨架屏**（v1.2 修正：v1 不播，见下）

| 状态 | 触发条件 | 表现 |

> if (snap === null) {

### 19.4 `fontScale` 的钳制规则（★ 会算错的地方）

`fontScale` 0/1/2 = 1.0 / 1.15 / 1.3，与 §7 的年级字号**叠加**。叠加后必须钳制，否则**高年级用户反而看到更小的字**：

| 年级 | 基准算式字号 | fontScale=2 (×1.3) | 钳制后下限 | 自动缩放下限 |
|---|---|---|---|---|
| 1—2 年级 | 72 | 93.6 | — | 66.2 |
| 3—4 年级 | 64 | 83.2 | — | 58.9 |
| 5—6 年级 | 56 | 72.8 | **56** | 41.5 → **钳到 56** |

**规则**：

```js
// eqFont = 年级基准 × fontScale 映射
const fs = FONT_SCALE[settings.fontScale];      // 0→1.0  1→1.15  2→1.3
let eqFont = grade.eqFont * fs;

// 钳制 1：算式数字不得低于该年级基准（即 fontScale 永不缩小）
eqFont = Math.max(eqFont, grade.eqFont);

// 钳制 2：自动缩放下限不得低于基准的 0.92（即放大效果不被缩放吃掉）
const shrinkFloor = grade.eqFont * 0.92;         // 例：五年级 56×0.92 = 51.5

// 钳制 3：算式最大字号不超过 88（再大就撑破白卡了）
eqFont = Math.min(eqFont, 88);
```

**同时需缩放的其他元素**（保证比例协调）：

### 24.4 `shrinkFloor` 基准（采纳 frontend-dev R16）

frontend-dev 指出：若 `shrinkFloor` 仍用原 `base`(72)，而实际基准是 `base+boost`(74)，则 `fontScale=1` 时会出现 `72 < 74` 的矛盾。

**正确规则：三道钳制全部基于 `b = base + boost`**：

```js
const b = gradeCfg.eqFont + (gradeCfg.fontBoost || 0);  // 例：72 + 2 = 74
const fs = FONT_SCALE[settings.fontScale];              // 0→1.0  1→1.15  2→1.3
let eqFont = b * fs;
eqFont = Math.max(eqFont, b);          // 钳1：不低于含 boost 的基准
const shrinkFloor = b * 0.92;          // 钳2：缩放下限也含 boost  ★这条是关键
eqFont = Math.min(eqFont, 88);         // 钳3：上限
```

> §19.4 原文写的 `shrinkFloor = grade.eqFont * 0.92` **未含 boost**，据此作废，改为 `b * 0.92`。
